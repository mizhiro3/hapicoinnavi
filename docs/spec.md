# はぴコイン使えるお店ナビ 現行仕様

## 1. 文書の目的

本書は、リポジトリ内の現行実装を基準に「はぴコイン使えるお店ナビ」の仕様を記述する。将来の構想や未実装機能は含まない。

## 2. サービス概要

福井県内のデジタル地域通貨（サイフ・ポイント）および紙商品券を選び、その支払手段を利用できる店舗を検索する静的 Web サイトである。

- サービス名: はぴコイン使えるお店ナビ
- 対象言語: 日本語
- 位置づけ: 非公式の加盟店検索サイト
- 主な利用端末: スマートフォンおよび PC
- 実行方式: HTML、CSS、JavaScript と JSON データで構成されたクライアントサイドアプリケーション
- 注意事項: 本サイトは公式な加盟証明や営業保証を行わない。営業時間や対応状況は参考情報であり、最新情報は店舗または公式案内で確認する必要がある。

## 3. 画面構成

### 3.1 共通ヘッダー

- サービス名と「ふくいはぴコインのお店探し」を表示する。
- 「非公式の加盟店検索サイト」であることを表示する。
- データの取得日時が有効な場合、「YYYY年M月D日時点の情報」と表示する。日付は日本時間として整形する。
- 「現在地は端末内だけで使用」と表示する。
- ブランド部分を押すとコイン選択画面へ戻る。
- キーボード利用者向けに「本文へ移動」リンクを設ける。

### 3.2 コイン選択画面

- 公開状態のコイン・商品券だけを表示する。
- 次の区分ごとに一覧表示する。
  - サイフ・ポイント（`kind: digital`。`kind` 未指定時も digital として扱う）
  - 紙商品券（`kind: paper`）
- 各項目にはロゴと名称を表示し、選択すると店舗検索画面へ遷移する。
- ロゴを読み込めない場合は、名称の先頭 1 文字を代替表示する。
- データ取得に失敗した場合は、時間を置いて再読み込みするよう案内する。

### 3.3 店舗検索画面

選択中のコインまたは紙商品券について、以下を表示する。

- 種別、ロゴ、名称、説明
- コインを選び直すボタン
- 店名・住所のキーワード入力欄
- 現在地利用パネル
- 検索結果件数
- 選択中のカテゴリ
- 並び順（「登録順」または「現在地から近い順」）
- 店舗カード一覧
- カテゴリナビゲーション

画面をスクロールして検索欄が上端に固定されたときは、固定検索欄内に選択中のコインを表示する。店舗検索画面で 400 px を超えてスクロールすると「ページトップ」ボタンを表示する。

## 4. 店舗検索

### 4.1 検索対象

次の条件をすべて満たす店舗を検索対象とする。

- 店舗が公開状態である。
- 選択中のコイン ID が店舗の `coinIds` に含まれる。
- 選択中のカテゴリ条件に合致する。
- キーワードが指定されている場合、検索対象文字列にキーワードを含む。

### 4.2 キーワード検索

検索対象は以下を連結した文字列である。

- 店舗名
- 検索補助語（読み仮名など）
- 住所の全項目

入力値と検索対象には次の正規化を行い、部分一致で判定する。

- Unicode NFKC 正規化（全角・半角などを統一）
- 日本語ロケールでの小文字化
- カタカナをひらがなに変換
- 空白文字を除去

入力のたびに検索結果を更新する。検索実行ボタンは設けない。

### 4.3 カテゴリ絞り込み

下部のカテゴリナビゲーションには、選択中のコインを利用できる公開店舗に基づく件数を表示する。

- すべて
- 食品
- ショッピング
- 飲食
- サービス
- カテゴリ（詳細カテゴリ選択ダイアログを開く）

大分類は、実装内で定義した複数の詳細カテゴリのいずれかを持つ店舗に一致する。該当店舗が 0 件の大分類は表示しない。同じ詳細カテゴリが複数の大分類に属する場合、店舗はそれぞれの大分類に含まれる。

詳細カテゴリダイアログには、選択中のコインに対して実在するカテゴリだけを表示する。表示順は店舗数の降順、同数の場合は日本語のカテゴリ名順とする。

### 4.4 並び順と距離

- 現在地を使用していない場合は、店舗 JSON 内の登録順を維持する。
- 現在地を取得した場合は、現在地から店舗座標までの直線距離が近い順に並べる。
- 距離は地球半径 6,371 km とした大円距離で計算する。
- 1 km 未満は「約N m」（メートル単位に丸める）、1 km 以上 10 km 未満は小数第 1 位、10 km 以上は整数の「約N km」で表示する。

### 4.5 段階表示

- 初回は検索結果の先頭 40 件を表示する。
- 以降も 40 件ずつ追加する。
- 「さらに表示」ボタン、またはその付近（上下 300 px の監視範囲）へのスクロールで追加表示する。
- 絞り込みや検索条件が変わると先頭から再描画する。

### 4.6 検索結果がない場合

- 「条件に合うお店がありません」と表示する。
- カテゴリを「すべて」に戻すか、検索語を短くするよう案内する。
- 「条件をすべて戻す」でカテゴリとキーワードを初期化する。
- 現在地および選択中のコインは初期化しない。

## 5. 位置情報

- 利用者が「現在地を使う」を押した場合にだけブラウザの Geolocation API を呼び出す。
- 高精度測位は要求しない。
- タイムアウトは 10 秒、キャッシュ済み位置情報の許容時間は 5 分とする。
- 取得した緯度・経度はブラウザ上の距離計算にのみ使用し、保存・サーバー送信しない。
- 取得成功後はボタンを「現在地を更新」に変更し、再取得できる。
- API 非対応、権限拒否、その他の取得失敗ごとに案内文を表示し、位置情報なしの検索を継続できる。

## 6. 店舗カード

店舗ごとに、存在する情報だけを使って以下を表示する。

- カテゴリ（複数可）
- サンプルデータである旨（`sample: true` の場合）
- 店舗名
- 郵便番号、都道府県、市区町村、番地、建物名を連結した住所
- 営業時間
- 定休日
- お知らせ
- Google マップへの外部リンク
- その店舗で利用できる公開中の全コイン・商品券のロゴ
- 現在地取得時の概算直線距離

Google マップの検索 URL は、店舗名と整形済み住所を検索語として生成し、新しいタブで開く。外部ページから元画面を操作されないよう `noopener noreferrer` を指定する。

営業時間、定休日、お知らせに含まれる `<br>` は改行として表示する。それ以外の HTML 文字列は HTML として解釈せず、文字として表示する。

## 7. URL と画面状態

- コイン選択時は URL のハッシュを `#coin=<コインID>` に置き換える。
- この URL を直接開いた場合、有効かつ公開中のコイン ID であれば店舗検索画面を表示する。
- 不明または非公開の ID の場合はコイン選択画面を表示する。
- コイン選択画面へ戻るとハッシュを除去する。
- カテゴリ、キーワード、現在地、表示件数は URL に保存しない。
- ブラウザ履歴には新しい履歴項目を追加せず、現在の履歴項目を置き換える。

## 8. データ仕様

### 8.1 コインデータ (`data/coins.json`)

配列形式。主な項目は以下のとおり。

| 項目 | 内容 |
| --- | --- |
| `id` | コインを識別する英小文字・数字・ハイフンの ID |
| `name` | 表示名 |
| `description` | 説明文 |
| `logo` | 同一オリジン内の SVG ロゴパス |
| `kind` | `digital` または `paper` |
| `displayOrder` | 表示順を示す値（画面は JSON の配列順で描画） |
| `published` | 公開可否 |
| `sourceId` | 取得元での識別子 |
| `sample` | サンプルデータか否か |

ロゴパスは `assets/coins/<英小文字・数字・ハイフン>.svg` の形式だけを許可し、外部 URL やディレクトリ移動を含むパスは使用しない。

### 8.2 店舗データ (`data/stores.json`)

配列形式。主な項目は以下のとおり。

| 項目 | 内容 |
| --- | --- |
| `id` | 店舗 ID |
| `name` | 店舗名 |
| `searchTerms` | 検索補助語の配列 |
| `coinIds` | 利用可能なコイン ID の配列 |
| `categories` | 詳細カテゴリ名の配列 |
| `address` | `postalCode`、`prefecture`、`city`、`street`、任意の `building` |
| `location` | `latitude`、`longitude` |
| `phone` | 電話番号（現行画面では表示しない） |
| `businessHours` | 営業時間 |
| `closedDays` | 定休日 |
| `notice` | 任意のお知らせ |
| `published` | 公開可否 |
| `updatedAt` | 店舗情報の更新日 |
| `sample` | サンプルデータか否か |

### 8.3 バージョンデータ (`data/version.json`)

| 項目 | 内容 |
| --- | --- |
| `version` | コイン、店舗、ロゴ取得時のキャッシュバスター |
| `crawledAt` | データ取得日時。ヘッダーの基準日表示に使用 |

### 8.4 現在のデータ規模

2026年8月29日取得の同梱データは以下のとおり。データ更新により件数は変動する。

- コイン・商品券: 43 種（デジタル 38 種、紙商品券 5 種。すべて公開中）
- 店舗: 4,782 件（すべて公開中）

## 9. データ取得とキャッシュ

1. 初期表示時に `version.json` を `no-store` で取得する。
2. 取得したバージョンをクエリに付け、`coins.json` を `force-cache` で取得する。
3. トップ画面では店舗データを取得しない。
4. コイン選択時に初めて `stores.json` をバージョン付き・`force-cache` で取得する。
5. 同一ページ内では店舗データと進行中の取得処理を再利用する。失敗した取得処理は破棄し、次回選択時に再試行可能とする。

店舗データ取得に失敗した場合は店舗検索画面に読込エラーを表示し、ページ再読み込みを案内する。

## 10. セキュリティとプライバシー

- Content Security Policy により、原則としてスクリプト、スタイル、画像、フォント、通信先を同一オリジンに限定する。画像のみ `data:` URI も許可する。
- オブジェクト埋め込み、`base` URI、フォーム送信を禁止する。
- HTTP リソースは HTTPS へのアップグレードを要求する。
- リファラーポリシーは `strict-origin-when-cross-origin` とする。
- データ由来の文字列は原則 `textContent` で描画し、HTML として挿入しない。
- 位置情報は永続化および外部送信をしない。

## 11. アクセシビリティと操作性

- 文書言語を日本語に設定する。
- 主要画面、検索欄、カテゴリナビゲーション、ダイアログにラベルを付ける。
- 動的なコイン一覧、検索結果、エラーにはライブリージョンまたはアラートを使用する。
- 選択式カテゴリは `aria-pressed` で状態を伝える。
- キーボードフォーカスを視覚表示する。
- カテゴリ詳細はモーダルダイアログとして表示し、閉じるボタンまたは背景クリックで閉じられる。
- 画面幅 760 px、430 px、360 px を境にレイアウトを調整する。
- OS の「視差効果を減らす」設定が有効な場合、ページトップ移動を即時にし、CSS のアニメーションとトランジションを抑制する。
- JavaScript が無効な場合は、店舗検索に JavaScript が必要である旨を表示する。

## 12. 対象外・現行の制約

- 店舗情報の登録、編集、削除を行う管理画面はない。
- ユーザーアカウント、ログイン、お気に入り、検索履歴の保存はない。
- 地図をサイト内には表示せず、Google マップの検索ページへ遷移する。
- ルート距離や所要時間は算出せず、表示距離は直線距離の目安である。
- 店舗への電話発信リンクは表示しない。
- 営業中かどうかのリアルタイム判定は行わない。
- サーバーサイド検索は行わず、取得済みデータをブラウザ内で検索する。

## 13. 動作環境・検証

- Node.js 20 以上を開発・テスト環境とする。
- テストは Node.js 標準のテストランナーで実行する。
- `npm test` でワークスペース内のテストを実行する。
- 現行テストは、文字列正規化、表示用改行処理、日付整形、検索・カテゴリ絞り込み、距離計算・並び順、Google マップ URL、固定表示条件、40 件単位の段階表示、ロゴパス検証を対象とする。
