# はぴコイン使えるお店ナビ 現行仕様

## 1. 文書の目的

本書は、リポジトリ内の現行実装を基準に「はぴコイン使えるお店ナビ」の仕様を記述する。将来の構想や未実装機能は含まない。

## 2. サービス概要

福井県内のデジタル地域通貨（サイフ・ポイント）および紙商品券を選び、その支払手段を利用できる店舗を検索する静的 Web サイトである。

- サービス名: はぴコイン使えるお店ナビ
- 対象言語: 日本語
- 位置づけ: 非公式の加盟店検索サイト
- 主な利用端末: スマートフォンおよび PC
- 実行方式: HTML、CSS、JavaScript と JSON データで構成されたクライアントサイドアプリケーション
- 注意事項: 本サイトは公式な加盟証明や営業保証を行わない。営業時間や対応状況は参考情報であり、最新情報は店舗または公式案内で確認する必要がある。

## 3. 画面構成

### 3.1 共通ヘッダー

- サービス名と「ふくいはぴコインのお店探し」を表示する。
- 「非公式の加盟店検索サイト」であることを表示する。
- データの取得日時が有効な場合、「YYYY年M月D日時点の情報」と表示する。日付は日本時間として整形する。
- 「現在地は端末内だけで使用」と表示する。
- ブランド部分を押すとコイン選択画面へ戻る。
- キーボード利用者向けに「本文へ移動」リンクを設ける。

### 3.2 コイン選択画面

- 公開状態のコイン・商品券だけを表示する。
- 次の区分ごとに、区分見出しと専用のグリッドで一覧表示する。
  - サイフ・ポイント（`kind: digital`。`kind` 未指定時も digital として扱う）
  - 紙商品券（`kind: paper`）
- 表示は区分ごとに異なる。
  - サイフ・ポイント: カード枠を設けず、ロゴ（アイコン）だけを大きく表示する。ロゴ画像内に名称が含まれるため、ロゴとは別の名称テキストは表示しない。
  - 紙商品券: ロゴ（アイコン）と名称テキストをカードとして横並びに表示する。
- 区分内の表示順は取得元サイトの掲載順（`displayOrder` の昇順）とする。
- いずれの区分も、項目を選択すると店舗検索画面へ遷移する。ボタンには「〇〇でお店を探す」というラベルを付け、名称テキストのない項目でも支援技術で名称を認識できるようにする。
- ロゴを読み込めない場合は、名称の先頭 1 文字を代替表示する。代替表示のときだけ角丸の枠と背景を付ける。
- コインのロゴ画像には、内容（枠や図柄）を削らない範囲で四隅にわずかな角丸を付ける。角丸の大きさは表示サイズに応じて調整し、いずれの区分・画面でも縁が欠けないようにする。
- グリッドの列数は画面幅に応じて切り替える。
  - サイフ・ポイント: PC で 6 列、760 px 以下で 4 列、360 px 以下で 3 列。
  - 紙商品券: PC で 2 列、360 px 以下で 1 列。
- データ取得に失敗した場合は、時間を置いて再読み込みするよう案内する。

### 3.3 店舗検索画面

選択中のコインまたは紙商品券について、以下を表示する。

- 種別、ロゴ、名称、説明
- コインを選び直すボタン
- 店名・住所のキーワード入力欄
- 現在地利用パネル
- 検索結果件数
- 選択中のカテゴリ
- 並び順（「登録順」または「現在地から近い順」）
- 店舗カード一覧
- カテゴリナビゲーション

画面をスクロールして検索欄が上端に固定されたときは、固定検索欄内に選択中のコインを表示する。店舗検索画面で 400 px を超えてスクロールすると「ページトップ」ボタンを表示する。

選択中コインのロゴおよび固定検索欄内のロゴには、内容を削らない範囲で四隅にわずかな角丸を付ける。角丸の大きさは表示サイズに応じて調整し、縁が欠けないようにする。ロゴを読み込めず先頭 1 文字を代替表示する場合は、角丸の枠と背景を付ける。

## 4. 店舗検索

### 4.1 検索対象

次の条件をすべて満たす店舗を検索対象とする。

- 店舗が公開状態である。
- 選択中のコイン ID が店舗の `coinIds` に含まれる。
- 選択中のカテゴリ条件に合致する。
- キーワードが指定されている場合、検索対象文字列にキーワードを含む。

### 4.2 キーワード検索

検索対象は以下を連結した文字列である。

- 店舗名
- 検索補助語（読み仮名など）
- 住所の全項目

入力値と検索対象には次の正規化を行い、部分一致で判定する。

- Unicode NFKC 正規化（全角・半角などを統一）
- 日本語ロケールでの小文字化
- カタカナをひらがなに変換
- 空白文字を除去

入力のたびに検索結果を更新する。検索実行ボタンは設けない。

### 4.3 カテゴリ絞り込み

下部のカテゴリナビゲーションには、選択中のコインを利用できる公開店舗に基づく件数を表示する。

- すべて
- 食品
- ショッピング
- 飲食
- サービス
- カテゴリ（詳細カテゴリ選択ダイアログを開く）

大分類は、実装内で定義した複数の詳細カテゴリのいずれかを持つ店舗に一致する。該当店舗が 0 件の大分類は表示しない。同じ詳細カテゴリが複数の大分類に属する場合、店舗はそれぞれの大分類に含まれる。

詳細カテゴリダイアログには、選択中のコインに対して実在するカテゴリだけを表示する。表示順は店舗数の降順、同数の場合は日本語のカテゴリ名順とする。

### 4.4 並び順と距離

- 現在地を使用していない場合は、店舗 JSON 内の登録順を維持する。
- 現在地を取得した場合は、現在地から店舗座標までの直線距離が近い順に並べる。
- 距離は地球半径 6,371 km とした大円距離で計算する。
- 1 km 未満は「約N m」（メートル単位に丸める）、1 km 以上 10 km 未満は小数第 1 位、10 km 以上は整数の「約N km」で表示する。

### 4.5 段階表示

- 初回は検索結果の先頭 40 件を表示する。
- 以降も 40 件ずつ追加する。
- 「さらに表示」ボタン、またはその付近（上下 300 px の監視範囲）へのスクロールで追加表示する。
- 絞り込みや検索条件が変わると先頭から再描画する。

### 4.6 検索結果がない場合

- 「条件に合うお店がありません」と表示する。
- カテゴリを「すべて」に戻すか、検索語を短くするよう案内する。
- 「条件をすべて戻す」でカテゴリとキーワードを初期化する。
- 現在地および選択中のコインは初期化しない。

## 5. 位置情報

- 利用者が「現在地を使う」を押した場合にだけブラウザの Geolocation API を呼び出す。
- 高精度測位は要求しない。
- タイムアウトは 10 秒、キャッシュ済み位置情報の許容時間は 5 分とする。
- 取得した緯度・経度はブラウザ上の距離計算にのみ使用し、保存・サーバー送信しない。
- 取得成功後はボタンを「現在地を更新」に変更し、再取得できる。
- API 非対応、権限拒否、その他の取得失敗ごとに案内文を表示し、位置情報なしの検索を継続できる。

## 6. 店舗カード

店舗ごとに、存在する情報だけを使って以下を表示する。

- カテゴリ（複数可）
- サンプルデータである旨（`sample: true` の場合）
- 店舗名
- 郵便番号、都道府県、市区町村、番地、建物名を連結した住所
- 営業時間
- 定休日
- お知らせ
- Google マップへの外部リンク
- その店舗で利用できる公開中の全コイン・商品券のロゴ
- 現在地取得時の概算直線距離

店舗カードに並べるコイン・商品券のロゴには、内容を削らない範囲で四隅にわずかな角丸を付ける。角丸の大きさは表示サイズに応じて調整し、縁が欠けないようにする。ロゴを読み込めず先頭 1 文字を代替表示する場合は、角丸の枠と背景を付ける。

Google マップの検索 URL は、店舗名と整形済み住所を検索語として生成し、新しいタブで開く。外部ページから元画面を操作されないよう `noopener noreferrer` を指定する。

営業時間、定休日、お知らせに含まれる `<br>` は改行として表示する。それ以外の HTML 文字列は HTML として解釈せず、文字として表示する。

## 7. URL と画面状態

- コイン選択時は URL のハッシュを `#coin=<コインID>` に置き換える。
- この URL を直接開いた場合、有効かつ公開中のコイン ID であれば店舗検索画面を表示する。
- 不明または非公開の ID の場合はコイン選択画面を表示する。
- コイン選択画面へ戻るとハッシュを除去する。
- カテゴリ、キーワード、現在地、表示件数は URL に保存しない。
- ブラウザ履歴には新しい履歴項目を追加せず、現在の履歴項目を置き換える。

## 8. データ仕様

### 8.1 コインデータ (`data/coins.json`)

配列形式。主な項目は以下のとおり。

| 項目 | 内容 |
| --- | --- |
| `id` | コインを識別する英小文字・数字・ハイフンの ID |
| `name` | 表示名 |
| `description` | 説明文 |
| `logo` | 同一オリジン内の SVG ロゴパス |
| `kind` | `digital` または `paper` |
| `displayOrder` | 区分内の表示順を示す値。取得元サイトの掲載順に対応し、ビルドで昇順に整列して出力する |
| `published` | 公開可否 |
| `sourceId` | 取得元での識別子 |
| `sample` | サンプルデータか否か |

ロゴパスは `assets/coins/<英小文字・数字・ハイフン>.svg` の形式だけを許可し、外部 URL やディレクトリ移動を含むパスは使用しない。

### 8.2 店舗データ (`data/stores.json`)

配列形式。主な項目は以下のとおり。

| 項目 | 内容 |
| --- | --- |
| `id` | 店舗 ID |
| `name` | 店舗名 |
| `searchTerms` | 検索補助語の配列 |
| `coinIds` | 利用可能なコイン ID の配列 |
| `categories` | 詳細カテゴリ名の配列 |
| `address` | `postalCode`、`prefecture`、`city`、`street`、任意の `building` |
| `location` | `latitude`、`longitude` |
| `phone` | 電話番号（現行画面では表示しない） |
| `businessHours` | 営業時間 |
| `closedDays` | 定休日 |
| `notice` | 任意のお知らせ |
| `published` | 公開可否 |
| `updatedAt` | 店舗情報の更新日 |
| `sample` | サンプルデータか否か |

### 8.3 バージョンデータ (`data/version.json`)

| 項目 | 内容 |
| --- | --- |
| `version` | コイン、店舗、ロゴ取得時のキャッシュバスター |
| `crawledAt` | データ取得日時。ヘッダーの基準日表示に使用 |

### 8.4 現在のデータ規模

2026年8月29日取得の同梱データは以下のとおり。データ更新により件数は変動する。

- コイン・商品券: 43 種（デジタル 38 種、紙商品券 5 種。すべて公開中）
- 店舗: 4,782 件（すべて公開中）

## 9. データ取得とキャッシュ

### 9.1 コイン画像の取得・加工フロー

コイン画像は、取得原本、恐竜キャラクター除去済み画像、画面表示用ドット絵の3段階で管理する。各段階で同じファイル名を使用し、コイン ID とファイル名を一致させる。

| ディレクトリ | 内容 | 更新方針 |
| --- | --- | --- |
| `apps/site/public/assets/coins_original` | クローラーが取得元サイトから取得したオリジナル画像 | 人手で加工せず、取得時の原本を保存する |
| `apps/site/public/assets/coins_del_chara` | オリジナル画像の画面中央右にいる恐竜キャラクターを除去した画像 | ドット絵生成の入力として使用する |
| `apps/site/public/assets/coins` | 恐竜除去済み画像から作成した画面表示用ドット絵 | Webサイトが参照する公開用画像とする |

たとえば、あわら市サイフは各段階で `awara-wallet.svg` という同じファイル名を使用する。紙商品券は複数の商品券から共通の `paper-voucher.svg` を参照する。

#### 9.1.1 取得前のバックアップ

コイン情報と画像を取得する前に、既存の次の3ディレクトリを日時付きのバックアップへコピーする。

- `coins_original`
- `coins_del_chara`
- `coins`

`npm run import:coins` は画像取得前に `tools/data-builder/backups/<日時>-before-coin-import/assets` へバックアップを作成する。手動で画像を作り直す場合も、対象となる `apps/site/public/assets/coins/<コインID>.svg` を上書き前にバックアップする。バックアップの作成と内容確認が終わるまでは既存画像を上書きしない。

#### 9.1.2 オリジナル画像の取得

次のコマンドで取得元サイトからコイン情報と画像を取得する。

```sh
npm run import:coins
```

取得した未加工画像は `apps/site/public/assets/coins_original/<コインID>.svg` に保存する。取得処理では、前回の原本と内容を比較して変更された画像を報告する。変更がない画像は再加工しなくてよい。取得失敗、SVG以外の応答、許可していない要素を含むSVG、2 MBを超える画像は公開工程へ進めない。

#### 9.1.3 恐竜キャラクターの除去

変更されたオリジナル画像を確認し、画面中央右にいる指定の恐竜キャラクターだけを除去する。コイン固有のロゴ、マスコット、配色、文字、背景、構図は変更しない。指定の恐竜が存在しない場合は、オリジナルの見た目をそのまま維持する。

加工後の画像は次へ保存する。

```text
apps/site/public/assets/coins_del_chara/<コインID>.svg
```

除去後は、不自然な欠け、背景の継ぎ目、コイン固有要素の消失がないことを目視確認する。`coins_original` のファイルは加工結果で上書きしない。

#### 9.1.4 ドット絵の生成

`apps/site/public/assets/coins/awara-wallet.svg` を公開用ドット絵の粒度、外枠、レイアウトの基準画像とし、`apps/site/public/assets/coins/bell-wallet.svg` をロゴとマスコットの黒い縁取り、および動物キャラクターの2頭身表現の基準画像とする。人物キャラクターの2頭身表現は `apps/site/public/assets/coins/echizencity-wallet.svg` を基準とする。各コインは `coins_del_chara` の画像を内容の参照元として、コインごとに個別に生成する。一括の単純縮小だけで済ませず、元画像の識別に必要な形を維持する。

確認済み画像の参照用途は次のとおりとする。新しい画像を生成するときは、内容が近い画像だけでなく、粒度の基準である `awara-wallet.svg` を必ず参照する。

| 画像 | 主な参照用途 |
| --- | --- |
| `awara-wallet.svg` | ドットの大きさ、外枠、上部図柄と下部名称帯の比率 |
| `bell-wallet.svg` | 白いロゴの内外の黒い縁取り、動物キャラクターの可愛い2頭身表現 |
| `childbirth-childcare-supportgifts.svg` | 文字を含まないシンボル主体の構成と、長い名称の2行表示 |
| `echizencity-wallet.svg` | 元の衣装、髪形、持ち物を維持した人物キャラクターの2頭身表現 |
| `eiheiji-wallet.svg` | 大きな顔と短い胴を持つ人物系マスコットの単体配置 |
| `fukui-wallet.svg` | 人型でないシンボルキャラクターを、識別できる粗いドットへ単純化する例 |
| `fukuibank-wallet.svg` | 丸い動物キャラクター、白い顔、翼、腕、持ち物を黒線で分離する例 |

生成時は次の条件を満たす。

- 正方形の画像とする。
- 上側およそ3分の2に、元画像のロゴまたはマスコットを配置する。
- 下側およそ3分の1を、サイフ名を表示するための暖色系クリーム色の帯とする。
- `awara-wallet.svg` と同程度の大きく粗いドット粒度にする。画像ごとに細かさを変えない。
- 初回生成のドットが `awara-wallet.svg` より細かい場合は、そのまま採用しない。元画像の特徴を維持したまま、見かけ上のドットを約1.5倍ずつ大きくして再生成し、輪郭の段差と内部線も同じ単位へそろえる。
- 粒度を粗くするときは、細い画像をぼかして拡大せず、曲線や細部をより少ない大きな正方形ブロックへ描き直す。孤立した小さなピクセルや、一部だけ細かい線を残さない。
- 主要な外形と内部要素を、連続した黒または黒に近い太い境界線で表す。
- ロゴが白色や背景と近い色であっても、背景との境界を省略せず黒く縁取る。
- ロゴ内部の切れ込み、段差、分割部分も、`bell-wallet.svg` の白いBellロゴと同様に黒いピクセル線で明確に分離する。
- 黒い縁取りは途中で欠けさせず、外周と内部形状のどちらも元のシルエットを判別できる太さにする。
- 元画像を識別できる主要なロゴ、マスコット、シンボル、配色を残す。
- 元画像に指定の恐竜以外の人物または動物キャラクターがいる場合は、そのキャラクターを削除しない。頭を大きく、胴、腕、脚を短くした、およそ2頭身の可愛いデフォルメ表現にする。
- 2頭身化するときも、元キャラクターの顔立ち、耳や髪形、衣装、配色、ポーズ、持ち物など、識別に必要な特徴を維持する。長い胴体や写実的な人体比率にしない。
- キャラクターの顔、頭、胴、手足、衣装、持ち物の境界も、縮小表示で判別できる太い黒いピクセル線で分離する。
- 色数を抑えた不透明なベタ色を使用する。
- グラデーション、アンチエイリアス、ぼかし、写真調の陰影、透かしを使用しない。
- 元画像にない文字、記号、人物、キャラクターを追加しない。
- 画像生成時にはサイフ名を描画しない。名称は後工程で正確な文字列を追加する。

画像生成に使用する指示の基準は次のとおり。

```text
元のコイン画像を、awara-wallet.svg と同じ粗い8-bit風ドット絵に変換する。
ロゴとマスコットの縁取りは bell-wallet.svg を基準にする。
上側3分の2に元のロゴまたはマスコットを置き、下側3分の1は空のクリーム色の帯にする。
大きな正方形ドット、太く連続した黒い輪郭、少数の不透明なベタ色を使用する。
外周に加え、ロゴ内部の切れ込み、段差、分割部分も黒いピクセル線で明確に縁取る。
元画像の識別に必要な形と配色を維持する。
元画像に人物または動物キャラクターがいる場合は、顔、衣装、配色、ポーズ、持ち物を維持しつつ、頭を大きく、胴と手足を短くした約2頭身にする。
動物キャラクターは bell-wallet.svg、人物キャラクターは echizencity-wallet.svg の可愛らしい頭身と黒い縁取りを基準にする。
文字、グラデーション、アンチエイリアス、ぼかし、影、透かし、追加要素は禁止する。
```

#### 9.1.5 サイフ名の追加とSVG化

生成画像の下部中央に、`coins.json` の `name` と完全に一致するサイフ名を追加する。画像生成モデルに文字を描かせず、SVGの `<text>` 要素として後から追加する。これにより、日本語の誤字や崩れを防ぐ。

公開ファイルは次へ保存する。

```text
apps/site/public/assets/coins/<コインID>.svg
```

SVGは `viewBox="0 0 320 320"` を基本とし、次を含める。

- アクセシビリティ用の `<title>` と `<desc>`
- 上部のドット絵
- 下部中央のサイフ名
- 普通の黒（`#000000`）かつ太字の、日本語を読みやすい文字

名称の表記と意味のまとまりは `coins_del_chara` の元画像を参考にする。長い名称は小さな1行へ詰め込まず、元画像の改行位置または語句のまとまりに沿って2行以上に分け、読みやすい文字サイズを維持する。複数行はSVGの `<tspan>` 要素で中央揃えにし、行間を確保する。左右で切れたり、行同士や上部のロゴへ重なったりしないことを確認する。ファイル名とコイン ID、`coins.json` の `logo` が一致していることも確認する。

サイフ名の描画方針は次のとおり。

- 文字色は普通の黒（`#000000`）、太字とする。
- 名称は下部のクリーム色帯に収める。帯の上端は固定値だけで判断せず、生成画像内の実際の黒い区切り線を確認し、その下側から外枠の内側までを文字エリアとして扱う。
- 意味の切れ目で改行し、括弧やサフィックス（「サイフ」「ポイント」「ウォレット」など）の途中では改行しない。括弧書き（例「ふく＋（小規模事業者応援）」）は括弧の前で改行し、括弧内では改行しない。
- 6文字程度までの短い名称は1行、それより長い名称は2〜3行に分ける。
- 文字サイズは、行数と各行の文字幅から帯の高さと横幅（左右に余白を確保した範囲）に収まる最大値を求めて決める。行数が同じでも名称によりサイズは異なってよい。
- 左右の枠に文字がかからないよう横方向の余白を確保する。
- 名称は原則としてクリーム色帯の縦方向中央へ配置する。上側の区切り線に近い場合だけ必要最小限下へ移動し、文字エリアの縦幅が十分大きい画像では下方向の補正を行わない。
- 個別の文字サイズや上下補正が必要な名称は `tools/data-builder/src/relabel-coin-images.js` の明示的なレイアウト設定で管理し、後の一括再ラベルで調整が失われないようにする。

これらの再ラベル処理は `tools/data-builder/src/relabel-coin-images.js` で一括生成できる。個別の改行位置は同スクリプトの明示ルールで管理し、`--write` を付けずに実行すると結果を確認できる。

#### 9.1.6 1画像ごとのドット絵化手順

クローラーで画像を取得した後は、コインごとに次の順序で作業する。途中生成物を直接公開せず、元画像、恐竜除去済み画像、公開用画像の3段階を混在させない。

1. `coins_original/<コインID>.svg` と `coins_del_chara/<コインID>.svg` を比較し、指定の恐竜だけが除去され、ロゴ、マスコット、文字、配色、構図が維持されていることを確認する。
2. 上書き対象の `coins/<コインID>.svg` を、日時付きバックアップディレクトリへ同じファイル名でコピーする。コピー後に元ファイルとバックアップの両方が存在することを確認する。
3. `coins_del_chara/<コインID>.svg`、`awara-wallet.svg`、`bell-wallet.svg` を参照して、文字を含まない320 px四方のドット絵を生成する。人物キャラクターを含む場合は `echizencity-wallet.svg` も参照する。生成指示は9.1.4の基準文を使用する。
4. 生成結果を一時PNGとして保存し、320 px表示で次を目視確認する。
   - `awara-wallet.svg` と同程度の大きなドット粒度である。
   - 640 px表示と320 px表示の両方で `awara-wallet.svg` と並べ、輪郭の段差や内部線だけが細かくなっていない。細かい場合は見かけ上のドットを約1.5倍大きくして再生成する。
   - 外周と内部の区切りが、途切れのない太い黒線になっている。
   - グラデーション、アンチエイリアス、ぼかし、透かし、誤った文字がない。
   - 元画像を識別するロゴ、マスコット、配色が残っている。
   - 人物または動物キャラクターがいる場合は約2頭身で、頭が大きく、胴と手足が短く、元の顔立ち、衣装、ポーズ、持ち物を識別できる。
   - 上側およそ3分の2に図柄、下側およそ3分の1に空のクリーム色帯がある。
5. 承認した一時PNGを `process-coin-image.js` の `--label-only` モードでSVGへ格納し、正確なサイフ名をSVGテキストとして追加する。`--preserve-source` を必ず指定し、`coins_del_chara` を上書きしない。

たとえば「出産・子育て応援ギフト」を2行で追加する場合は、次のように実行する。

```sh
npm run process:coin-image -- \
  --input /tmp/childbirth-childcare-supportgifts.png \
  --id childbirth-childcare-supportgifts \
  --title '出産・子育て応援ギフト' \
  --label-lines '出産・子育て|応援ギフト' \
  --font-size 32 \
  --label-only \
  --preserve-source
```

`--title` は `coins.json` の `name` と完全に一致させる。`--label-lines` では表示する行を `|` で区切り、元画像の改行位置または意味のまとまりを維持する。文字サイズは固定値ではなく、全行が左右の枠と上下の図柄に重ならず、縮小表示でも読める最大値へ調整する。

既存画像の名称だけを一括調整する場合は、最初に書き込みなしで変更内容を確認し、その後に書き込む。

```sh
node tools/data-builder/src/relabel-coin-images.js
node tools/data-builder/src/relabel-coin-images.js --write
```

一括処理でも、書き込み前のバックアップと、書き込み後の全画像の目視確認を省略しない。ドット絵そのものを作り直す場合は一括再ラベル処理ではなく、各画像について手順1〜5を行う。

#### 9.1.7 公開前の確認

各画像について次を確認する。

1. `coins_original` にクローラー取得時の原本が残っている。
2. `coins_del_chara` では指定の恐竜だけが除去され、その他の意匠が維持されている。
3. `coins` の画像が `awara-wallet.svg` と同程度のドット粒度、外枠、レイアウト、ベタ色になっている。
4. 輪郭、曲線の段差、内部線のピクセル単位が画像全体で統一され、`awara-wallet.svg` より細かい部分や孤立した小さなピクセルが残っていない。
5. ロゴとマスコットの外周および内部形状が、`bell-wallet.svg` と同様に太く連続した黒いピクセル線で縁取られている。
6. 元のコインを識別できるロゴまたはマスコットが残っている。
7. 人物または動物キャラクターがいる場合は、`echizencity-wallet.svg` または `bell-wallet.svg` と同様の約2頭身であり、元のキャラクターの特徴、ポーズ、持ち物が維持されている。
8. 下部に正しいサイフ名が普通の黒・太字で表示され、意味の切れ目で改行された各行が下部帯に収まり、文字切れ、左右の枠へのはみ出し、上部ロゴとの重なりがない。
9. 文字エリアの縦幅が十分大きい画像は名称が帯の中央にあり、不要な下方向の補正が行われていない。
10. 320 px 四方での表示と、実際のコイン選択画面の縮小表示の両方で判別できる。
11. `npm test` と `npm run validate:data` が成功する。

公開画像を変更した場合は、ブラウザに古い画像が残らないよう `apps/site/public/data/version.json` の `version` を更新する。確認で問題が見つかった場合は公開せず、バックアップから直前の画像を復元する。

### 9.2 画面データの取得とキャッシュ

1. 初期表示時に `version.json` を `no-store` で取得する。
2. 取得したバージョンをクエリに付け、`coins.json` を `force-cache` で取得する。
3. トップ画面では店舗データを取得しない。
4. コイン選択時に初めて `stores.json` をバージョン付き・`force-cache` で取得する。
5. 同一ページ内では店舗データと進行中の取得処理を再利用する。失敗した取得処理は破棄し、次回選択時に再試行可能とする。

店舗データ取得に失敗した場合は店舗検索画面に読込エラーを表示し、ページ再読み込みを案内する。

## 10. セキュリティとプライバシー

- Content Security Policy により、原則としてスクリプト、スタイル、画像、フォント、通信先を同一オリジンに限定する。画像のみ `data:` URI も許可する。
- オブジェクト埋め込み、`base` URI、フォーム送信を禁止する。
- HTTP リソースは HTTPS へのアップグレードを要求する。
- リファラーポリシーは `strict-origin-when-cross-origin` とする。
- データ由来の文字列は原則 `textContent` で描画し、HTML として挿入しない。
- 位置情報は永続化および外部送信をしない。

## 11. アクセシビリティと操作性

- 文書言語を日本語に設定する。
- 主要画面、検索欄、カテゴリナビゲーション、ダイアログにラベルを付ける。
- 動的なコイン一覧、検索結果、エラーにはライブリージョンまたはアラートを使用する。
- 選択式カテゴリは `aria-pressed` で状態を伝える。
- キーボードフォーカスを視覚表示する。
- カテゴリ詳細はモーダルダイアログとして表示し、閉じるボタンまたは背景クリックで閉じられる。
- 画面幅 760 px、430 px、360 px を境にレイアウトを調整する。
- OS の「視差効果を減らす」設定が有効な場合、ページトップ移動を即時にし、CSS のアニメーションとトランジションを抑制する。
- JavaScript が無効な場合は、店舗検索に JavaScript が必要である旨を表示する。

## 12. 対象外・現行の制約

- 店舗情報の登録、編集、削除を行う管理画面はない。
- ユーザーアカウント、ログイン、お気に入り、検索履歴の保存はない。
- 地図をサイト内には表示せず、Google マップの検索ページへ遷移する。
- ルート距離や所要時間は算出せず、表示距離は直線距離の目安である。
- 店舗への電話発信リンクは表示しない。
- 営業中かどうかのリアルタイム判定は行わない。
- サーバーサイド検索は行わず、取得済みデータをブラウザ内で検索する。

## 13. 動作環境・検証

- Node.js 20 以上を開発・テスト環境とする。
- テストは Node.js 標準のテストランナーで実行する。
- `npm test` でワークスペース内のテストを実行する。
- 現行テストは、文字列正規化、表示用改行処理、日付整形、検索・カテゴリ絞り込み、距離計算・並び順、Google マップ URL、固定表示条件、40 件単位の段階表示、ロゴパス検証を対象とする。
